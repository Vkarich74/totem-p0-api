# Auth security cutover — source-only, release gate
The deployed source exposes an obsolete login route without credential verification. Current SDK main uses API_BASE + /internal and canonical password/role-bound OTP and dedicated password-reset paths. Retire obsolete /auth login/start/verify and cookie identity resolve. Only signed version-2 session JWTs from verified canonical password/role-bound login OTP and admin password issuers accepted; all pre-cutover session-bearing tokens require sign-in again. Internal sessionless system/owner token behavior unchanged. Legacy unscoped verification cannot mint an account session; the dedicated reset routes remain. No session database migration, secret rotation, production changes or live probing. Existing sessions without provenance cannot be identified reliably; rejecting tokens is deliberately broad, includes legitimate old users. Rollout needs exact SDK/Admin/browser password/OTP/reset tests in staging, active-session count and incident review of password/account changes, coordinated reauthentication, deployment of all validators together, no rollback to insecure legacy route. The CI tests cover legacy HTTP retirement, marker and middleware contract, not full password/OTP/reset path or actual incident review. Do not claim full production security until those gates and deployment/readback.
